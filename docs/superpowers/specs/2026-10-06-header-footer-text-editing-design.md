# 머리말·꼬리말 글자 편집 설계

## 목적

HwpStudio에서 기존 HWP/HWPX 문서의 머리말·꼬리말을 문서 위에서 직접 고친다. 과제 양식의 쪽 번호와 제목처럼 반복되는 내용을 수정해도 표·본문·그림과 원본 조판이 변하지 않아야 한다.

성공 조건은 다음과 같다.

- 머리말 또는 꼬리말의 글자를 더블클릭하면 해당 단어가 선택되고 그 영역의 편집이 시작된다.
- 입력, 선택 교체, 삭제, 문단 나누기와 합치기, 글자 모양과 문단 모양이 본문과 같은 방식으로 동작한다.
- 본문을 클릭하면 머리말·꼬리말 편집에서 자연스럽게 빠져나온다.
- 양쪽·홀수쪽·짝수쪽 정의 중 화면에 보이는 정의만 수정한다.
- 실행 취소·다시 실행과 HWP/HWPX 저장 후 다시 열기가 내용과 조판을 보존한다.
- 머리말·꼬리말이 아닌 문서 내용은 편집 전후에 동일하다.

## 범위

이번 단계는 **이미 존재하며 화면에 글자가 보이는 머리말·꼬리말의 인라인 글자 편집**을 지원한다.

포함하는 기능:

- 더블클릭으로 편집 진입
- 클릭·드래그 선택, Shift 확장 선택, 모두 선택의 현재 컨테이너 범위
- 평문 입력과 붙이기, 한글 조합, 선택 교체
- Delete·Backspace, Enter, 문단 시작에서 Backspace
- 글자 모양과 문단 모양의 조회와 적용
- 찾기·복사·오려 두기처럼 기존 선택 기반 동작 중 컨테이너에서 안전한 동작
- Undo/Redo, HWP/HWPX 저장·다시 열기

제외하는 기능:

- 빈 위·아래 여백을 더블클릭하여 머리말·꼬리말을 자동 생성하는 동작
- 머리말·꼬리말 안의 그림·수식·표·도형 편집
- 서로 다른 머리말·꼬리말 정의 또는 본문까지 걸친 선택
- 양쪽·홀수쪽·짝수쪽 정의를 바꾸는 UI
- 현재 쪽 번호·전체 쪽 수·파일 이름 필드의 새 삽입 UI
- 이름이 붙은 문서 스타일을 머리말·꼬리말 문단에 적용하는 기능

새 머리말·꼬리말 생성과 쪽 번호 배치는 기존 `쪽` 메뉴를 그대로 사용한다. 제외 항목은 이번 구현의 안정성을 확인한 뒤 별도 단계로 다룬다.

## 선택한 접근

기존 편집 파이프라인을 확장한다. `EditTarget`에 머리말·꼬리말 메타데이터를 추가하고, 본문·표 셀·각주와 동일한 `EditPosition`·`EditSelection`·`EditCommand`를 사용한다.

별도 팝업 편집기는 문서 위 직접 편집이라는 목표를 충족하지 못한다. 머리말·꼬리말 전용 명령 체계를 따로 만드는 방식은 입력기, Undo, 선택, 서식 코드를 중복시킨다. 기존 파이프라인 확장은 rhwp가 제공하는 네이티브 머리말·꼬리말 API를 얇게 연결하면서 현재의 실패 롤백과 직렬 편집 규칙도 재사용한다.

## 편집 대상 모델

프로토콜 버전을 2에서 3으로 올리고 Rust와 Swift의 `EditTarget`에 선택적 `headerFooter`를 추가한다.

```text
HeaderFooterTarget
  footer: Bool       // false: 머리말, true: 꼬리말
  applyTo: UInt8     // 0: 양쪽, 1: 짝수쪽, 2: 홀수쪽
  page: UInt32       // 사용자가 편집을 시작한 표시 페이지

EditTarget
  section: UInt32    // 정의가 저장된 원본 구역
  paragraph: UInt32  // 머리말·꼬리말 내부 문단 번호
  cell: CellTarget?
  note: NoteTarget?
  headerFooter: HeaderFooterTarget?
```

`cell`, `note`, `headerFooter`는 서로 배타적이다. 머리말·꼬리말 정의가 앞 구역에서 상속된 경우 `section`은 화면 쪽이 속한 구역이 아니라 정의의 원본 구역을 가리킨다. `page`는 같은 내용이 여러 쪽에 반복되더라도 커서와 선택 영역을 사용자가 누른 쪽에 표시하기 위한 힌트다.

프로토콜 버전 불일치는 현재와 같이 문서를 열 때 거부한다. 구버전 앱과 엔진이 새 대상 구조를 조용히 잘못 해석하지 않게 한다.

## 진입과 화면 동작

일반 상태의 한 번 클릭은 지금처럼 본문·표·각주·개체를 선택한다. 더블클릭일 때 머리말과 꼬리말의 네이티브 히트 테스트를 먼저 시도하며, 성공하면 해당 단어를 선택하고 머리말·꼬리말 편집 상태가 된다. 편집 상태는 현재 선택의 `EditTarget.headerFooter` 존재 여부로 판단하며 별도 상태 값은 두지 않는다.

1. 캔버스가 더블클릭이거나 현재 선택이 머리말·꼬리말일 때 페이지 좌표와 `includeHeaderFooter = true`로 히트 테스트를 요청한다.
2. 엔진은 머리말과 꼬리말의 `hit_test_in_header_footer_native`를 확인한다.
3. 글자 영역에 맞으면 `sectionIndex`, `applyTo`, 내부 문단, 문자 위치와 클릭 페이지를 `EditPosition`으로 만든다.
4. 맞으면 기존 단어 시작·끝 이동을 사용해 단어를 선택한다. 맞지 않으면 기존 본문 히트 테스트로 이어진다.

편집 상태에서는 한 번 클릭과 드래그 선택도 머리말·꼬리말 히트 테스트를 사용한다. 빈 여백이나 글자가 없는 머리말·꼬리말은 이번 단계에서 편집 상태에 들어가지 않는다. 본문을 클릭하면 머리말·꼬리말 히트가 실패한 뒤 본문 `EditTarget`으로 선택이 교체되어 편집 상태에서 빠져나온다. 커서와 선택 영역은 기존 캔버스 표시를 사용한다.

## 엔진 데이터 흐름

### 조회와 위치 계산

- 문단 텍스트와 길이: `get_header_footer_para_info_native`
- 클릭 위치: `hit_test_in_header_footer_native`
- 커서: `get_cursor_rect_in_header_footer_native`
- 선택 영역: `get_selection_rects_in_header_footer_native`
- 글자 속성: `get_char_properties_in_header_footer_native`
- 문단 속성: `get_para_properties_in_hf_native`

커서 계산은 `HeaderFooterTarget.page`를 우선 사용한다. 재조판 후 그 쪽에 해당 정의가 더 이상 적용되지 않으면 엔진이 해당 정의가 실제 적용되는 첫 쪽을 찾아 표시한다. 선택 영역은 커서가 결정한 같은 쪽에서 계산한다.

머리말·꼬리말에는 본문용 보정 위치 목록(`stops`)을 사용하지 않고 rhwp 네이티브 좌표를 신뢰한다. 이후 인라인 개체 편집을 추가할 때 별도의 머리말·꼬리말 위치 보정이 필요하다.

### 내용 편집

- 선택 교체와 입력: `replace_range_in_header_footer_native`
- Enter: `split_paragraph_in_header_footer_native`
- 문단 시작 Backspace: `merge_paragraph_in_header_footer_native`
- 글자 모양: `apply_char_format_in_header_footer_native`
- 문단 모양: `apply_para_format_in_hf_native`

기존 `Replace`, `Split`, `MergePrevious`, `FormatText`, `FormatParagraphs` 명령이 대상 종류를 보고 위 API로 분기한다. `ApplyStyle`은 rhwp에 머리말·꼬리말용 대응 API가 없으므로 명시적으로 거부한다. 선택 교체는 단일 API로 처리하여 ⌘A 뒤 입력, 여러 문단 삭제, 줄바꿈이 포함된 붙이기를 원자적 편집 한 번으로 유지한다.

문단 이동과 선택 확장은 `EditTarget.paragraph`를 머리말·꼬리말 내부 문단 번호로 해석한다. 첫 문단의 앞이나 마지막 문단의 뒤에서 본문 또는 다른 머리말·꼬리말로 넘어가지 않는다.

### 실행 취소와 표시 갱신

현재 편집 세션의 명령 전 스냅샷, 실패 롤백, revision 증가, 바뀐 쪽 비교를 그대로 사용한다. 한 정의를 바꾸면 그 정의가 적용된 여러 쪽이 바뀔 수 있으므로 표시 해시 비교 결과에 포함된 모든 변경 쪽을 갱신한다.

## 구성 요소별 변경

### Rust 편집 엔진

- `protocol.rs`: `HeaderFooterTarget`, `EditTarget.header_footer`, 프로토콜 버전 3
- `geometry.rs`: 선택적 머리말·꼬리말 히트 테스트, 커서와 선택 사각형 분기
- `commands.rs`: 문단 조회, 교체, 분할, 합치기, 글자·문단 서식 분기
- `navigation.rs`와 `logical.rs`: 같은 머리말·꼬리말 정의 안에서만 이동·선택
- `format.rs`: 현재 글자·문단 속성 조회 분기
- `preservation.rs`: 머리말·꼬리말 명령의 허용 범위와 비대상 보존 검사

필요하면 분기 코드는 `editing/header_footer.rs`로 모아 `commands.rs`와 `geometry.rs`가 rhwp 인수 변환을 중복하지 않게 한다.

### Swift 앱

- `EditProtocol.swift`: Rust와 같은 대상 구조와 버전 3
- `EditSession.swift`: 머리말·꼬리말 포함 여부를 전달하는 히트 테스트
- `HwpDocument.swift`: 기존 선택·입력·서식 흐름을 변경하지 않고 새 대상 응답을 수용
- `DocumentCanvas.swift`: 더블클릭 또는 현재 머리말·꼬리말 선택 상태에서 히트 테스트를 허용

메뉴와 도구 상자는 현재 선택의 속성 조회 결과를 쓰므로 별도 머리말·꼬리말 전용 도구를 만들지 않는다. 이번 단계에서 UI 배치나 디자인은 바꾸지 않는다.

## 오류 처리와 안전성

- 정의가 삭제되거나 적용 대상이 바뀌어 더 이상 찾을 수 없으면 명령은 `UnsupportedTarget`으로 실패하고 문서 스냅샷을 복구한다.
- 선택의 두 끝이 서로 다른 정의, 머리말/꼬리말 종류, `applyTo` 또는 표시 페이지를 가지면 명령을 거부한다.
- 내부 문단과 문자 위치는 mutation 전에 검증한다.
- 빈 머리말·꼬리말 생성은 하지 않으므로 히트 실패는 오류 메시지 없이 기존 본문 동작으로 폴백한다.
- 저장은 기존과 같이 모든 대기 편집을 기다리고, 내보낸 파일을 다시 파싱한 뒤 원자적으로 교체한다.
- 오류 로그에는 대상 종류와 숫자 식별자만 남기며 문서 본문은 남기지 않는다.

## 검증 전략

구현은 테스트 우선으로 진행한다.

### Rust 단위·통합 테스트

- 더블클릭용 히트 테스트가 머리말과 꼬리말 글자에서 정확한 위치를 반환한다.
- 한 번 클릭 경로에서는 머리말·꼬리말 대상이 반환되지 않는다.
- 삽입, 선택 교체, Delete, Backspace, Enter, 문단 합치기의 선택과 커서가 맞다.
- 여러 문단 선택 교체와 줄바꿈 붙이기가 한 명령으로 동작한다.
- 글자 모양과 문단 모양 적용 후 조회값과 조판이 갱신된다.
- Undo/Redo 후 내용, 선택, 쪽 수와 표시 결과가 복구된다.
- 양쪽·홀수쪽·짝수쪽 및 앞 구역에서 상속된 정의 중 클릭한 정의만 바뀐다.
- HWP와 HWPX 각각 저장 후 다시 열어 내용·적용 범위·서식을 확인한다.
- 비대상 본문·표·그림의 직렬화 구조가 동일하다.
- 잘못된 대상과 강제 렌더 실패가 revision과 문서를 바꾸지 않는다.

### Swift 테스트

- 프로토콜 버전과 새 대상의 JSON 왕복
- 일반 상태의 더블클릭은 머리말·꼬리말을 포함하고 한 번 클릭은 포함하지 않으며, 편집 상태의 한 번 클릭과 드래그는 포함하는 요청
- 머리말·꼬리말 선택에서 입력, ⌘A 뒤 입력, Enter, Backspace, 서식 명령 전달
- 본문 클릭 후 선택 대상이 본문으로 전환

### 수동 확인

- 실제 macOS 한글 입력기로 연속 음절 조합, 후보창 위치, 확정, Undo
- 머리말과 꼬리말 더블클릭, 드래그 선택, 본문으로 빠져나오기
- 같은 정의가 반복되는 여러 쪽의 동시 갱신
- 홀수쪽·짝수쪽이 다른 문서
- HWP와 HWPX 저장 후 HwpStudio와 한컴 뷰어에서 다시 열어 조판 비교

수동 확인을 마치기 전에는 기능을 완료로 표시하지 않는다.

## 완료 기준

자동 테스트가 모두 통과하고, 실제 HWP/HWPX 표본에서 입력·삭제·문단·서식·Undo·저장·재열기와 한글 조합을 수동 확인한다. `docs/ROADMAP.md`의 항목은 이 검증이 끝난 뒤에만 완료로 바꾼다.
