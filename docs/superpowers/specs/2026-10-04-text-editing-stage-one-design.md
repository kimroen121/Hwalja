# HwpStudio 텍스트 편집 1단계 설계

상태: 검토 요청. 제품 코드는 아직 변경하지 않음.
날짜: 2026-10-04

## 목적과 전제

학교 HWP/HWPX 양식을 원본 훼손 없이 편집하는 로컬 macOS 앱을 만든다.
첫 편집 단계는 본문과 표 셀의 한글 입력·삭제·선택·실행 취소 및 편집 결과 PDF 확인이다.
기존 작업실형 UI, 표·그림 보존, 화면과 PDF의 동일한 조판 결과를 유지한다.
현재 한컴과 일부 쪽 나눔·표 여백·굵은 글꼴 차이가 남아 있으므로 편집 기능 추가를 호환성 완성으로 표시하지 않는다.

## 접근 선택

1. 권장: 현재 페이지 위에 입력·선택 계층을 올린다. 엔진이 문서 위치와 커서 좌표를 결정한다.
   화면에서 바로 편집할 수 있고 조판을 한 곳에서 처리하지만 좌표와 한글 조합 연결 검증이 필요하다.
2. 대안: 별도 문단 입력창과 PDF 미리보기를 연결한다.
   구현은 단순하지만 문서 위의 커서·표 셀 선택과 다른 사용 경험이다.
3. 비권장: PDF 글자 자체를 수정한다.
   원본 표·문단·그림 기준점과 연결되지 않아 HWP 편집 및 안전 저장의 기반으로 사용할 수 없다.

본 설계는 1번을 기준으로 한다. 기존 PDF 보기 모드는 유지하며 편집 모드를 명시적으로 켠다.

## 첫 단계 범위

- 일반 본문 및 최상위 표 셀 안의 일반 텍스트 문단을 클릭해 커서를 둔다.
- 같은 문단 안에서 키보드·마우스 선택, 삽입, 삭제, 선택 영역 교체와 일반 텍스트 붙여넣기를 지원한다.
- 한글 조합, 영문, 숫자, 이모지와 결합 문자를 지원한다.
- 같은 본문 또는 같은 셀에서 일반 문단 Enter 분할과 Backspace 병합을 지원한다.
- 조합 확정·붙여넣기·문단 분할 등을 실행 취소 단위로 기록한다.
- 확정된 수정은 재조판해 화면과 PDF에 함께 반영한다.
- 페이지 경계를 넘는 같은 문단 선택은 지원하되 여러 셀·서로 다른 컨테이너에 걸친 선택은 차단한다.
- 그림·수식·필드·주석 등 컨트롤이 들어 있는 문단, 중첩 표, 머리말·꼬리말·각주는 첫 단계에서 읽기 전용이다.
  차단 이유를 표시하며 숨은 컨트롤을 삭제하거나 평문으로 바꾸지 않는다.
- 표 구조·병합·행 높이 변경, 그림 이동·크기 변경, 수식 입력, 문자·문단 서식 도구는 후속 단계다.
- HWP/HWPX 저장 및 자동 복구는 후속 단계다. 현재 편집은 실험 기능으로 표시하고 원본 쓰기 경로를 열지 않는다.

위의 제한은 최종 제품 범위를 줄이는 것이 아니라 첫 구현의 검증 경계다.
과제 제출용 완성 편집기라는 표시는 저장·복구 및 호환성 검증이 갖춰진 뒤에만 한다.

## 구성과 데이터 흐름

원본 바이트 → Rust 편집 세션 → 명령 검증·적용 → 재조판·검사
→ 같은 revision의 PDF·커서·선택 좌표 → macOS 화면과 PDF 내보내기

### Rust 편집 세션

현재 HwpSnapshot은 PDF만 가진다. 별도 불투명 세션 핸들이 DocumentCore, 원본 바이트,
revision, undo/redo 상태를 소유하도록 확장한다. 기존 읽기 전용 API는 유지한다.
C ABI에서는 버전이 있는 요청·응답과 명시적인 free 함수를 사용한다.
Swift로 upstream 구조체나 빌린 메모리를 오래 넘기지 않는다.

각 위치는 section, 본문 문단, 선택적 표·셀 경로, 셀 문단, 문자 오프셋과 revision으로 표현한다.
구조 변경 시 인덱스가 달라질 수 있으므로 과거 revision의 위치를 조용히 재사용하지 않는다.
명령이 새 커서 위치를 반환하며 화면의 선택도 해당 revision으로 갱신한다.

삽입·삭제·분할·병합 전에 대상과 컨트롤, 문자열 범위, 크기 제한을 검증한다.
명령 전 엔진 스냅샷을 보관하고 실패하면 복원한다. PDF 생성·검사 완료 전에는
새 revision을 UI에 공개하지 않는다. 복원도 실패하면 세션을 오류 상태로 잠그고
마지막 정상 PDF와 원본 바이트는 유지한다.

확인한 upstream 기반:
- insert_text_native / delete_text_native
- insert_text_in_cell_native 및 셀 경로 기반 입력·삭제·분할·병합
- hit_test_native / get_cursor_rect_native / get_cursor_rect_in_cell_native
- save_snapshot_native / restore_snapshot_native / discard_snapshot_native

이 API들의 존재가 실제 문서에서의 정확성을 보장하지 않으므로 어댑터 계약 검사가 선행된다.

### macOS 입력 계층

AppKit NSTextInputClient 기반 입력 계층이 키보드, 조합 중 문자열, 후보창 위치와 선택을 처리한다.
PDFKit은 읽기 화면·쪽 탐색을 맡고 편집 모드의 클릭과 키 입력은 입력 계층이 소유한다.
PDFKit의 텍스트 선택을 HWP 위치로 해석하지 않는다.

PDF 좌표는 pt·하단 원점, 엔진은 현재 96dpi·상단 원점이다.
페이지 크기·회전·확대율·스크롤 위치를 반영하는 단일 변환 함수로 왕복한다.
지원하지 않는 회전 페이지는 편집을 차단한다. 변환은 페이지별로 검사한다.

Cocoa NSRange는 UTF-16, upstream 입력 오프셋은 문자 단위이므로 변환을 명시한다.
사용자가 보는 커서·삭제 경계는 grapheme cluster에 맞추며 surrogate/결합 문자를 나누지 않는다.
조합 중 문자열은 UI 임시 상태에 두고 확정할 때 한 번만 엔진 명령으로 기록한다.
후보창 위치는 최신 엔진 커서 위치로 반환한다. 포커스 변경·Undo·내보내기 전에
조합을 확정하거나 사용자가 취소할 수 있게 하며 조합 중 데이터를 몰래 버리지 않는다.

### 작업 직렬화와 화면 갱신

단일 직렬 작업 경로만 세션 핸들에 접근한다. 메인 스레드에서는 조판하지 않는다.
첫 버전은 확정 명령 처리 중 추가 편집을 잠시 막아 경쟁 상태를 피한다.
오래된 비동기 응답은 세션 ID와 revision 검사로 폐기한다.
PDF 교체 시 문서 내 커서 위치를 기준으로 스크롤·확대 상태를 복원한다.
매 키마다 원본을 다시 파싱하거나 파일로 저장하지 않는다.

### 실행 취소와 자원 관리

한글 조합 확정 1회, 붙여넣기 1회, Enter 1회는 각각 하나의 명령이다.
첫 버전에서 일반 입력도 명시적인 확정 명령 단위로 되돌린다.
새 편집을 하면 redo를 비운다. Undo/Redo도 PDF·커서·revision을 함께 복원한다.
초기에는 최대 20개 스냅샷을 보관하며 초과 항목은 discard한다.
대형 문서 메모리 시험을 통과하지 못하면 스냅샷 한도를 더 낮추고 사용자에게 알린다.
원본 바이트와 마지막 정상 결과를 undo 한도 때문에 버리지 않는다.

## 보존·실패·내보내기

- 편집 전후 표 행·열·병합·컨트롤 수·이미지 원본 데이터 및 미편집 문단을 비교한다.
- 구조 보존 실패·렌더 실패·자원 한도 초과 시 해당 명령을 취소하고 기존 상태로 돌아간다.
- 페이지 수 변화는 변경 내용으로 알린다. 6쪽이라는 특정 결과를 강제하지 않는다.
- 기존 겹침·용지 밖 글자 검사를 재사용한다. 의심 결과는 표시하고
  기존의 명시적 확인을 거친 검사용 PDF만 내보낼 수 있게 한다.
- 내보내기는 최신 확정 revision의 PDF만 사용한다. 처리 중에는 비활성화한다.
- 미저장 변경이 있는 창 닫기·파일 열기·앱 종료 시 취소 또는 변경 버리기를 묻는다.
  PDF는 편집 가능한 복구본이 아님을 명시한다.
- 이 단계에는 디스크 복구 기능이 없으므로 충돌·강제 종료 때 미저장 변경이 사라질 수 있다.
  편집 모드 진입 시 고지하며 기본 읽기 모드에는 영향을 주지 않는다.
- 로그와 저장소에 사용자의 보고서 본문·원본 파일을 넣지 않는다.

## 완료 기준과 검사

1. 생성한 HWP/HWPX의 본문 및 표 셀 텍스트를 편집한 뒤 구조·이미지가 보존된다.
2. 한글 조합 확정/취소, 방향키, 선택 교체, 이모지 삭제가 문자 경계를 깨뜨리지 않는다.
3. Enter·Backspace 후 문단 경계·스타일과 커서가 일관된다.
4. Undo→Redo가 텍스트·서식·컨트롤·커서 및 조판 결과를 복원한다.
5. 오류 주입으로 수정·렌더 실패 시 revision과 이전 문서가 유지됨을 확인한다.
6. 서로 다른 확대율·스크롤·쪽 경계에서 클릭 위치와 커서 표시가 맞는다.
7. 셀 밖 삭제·컨트롤 포함 문단·중첩 표는 명확한 메시지로 차단된다.
8. 편집 후 PDF의 본문과 화면이 같은 revision이며 원본 해시가 변하지 않는다.
9. 제공된 보고서의 안전한 텍스트 문단을 짧게 수정하고 되돌리는 로컬 검사를 수행한다.
10. 기존 읽기·PDF 출력·원본 보호·쪽 이동 검사가 계속 통과한다.

자동 검사 외에 실제 macOS 한글 입력기로 수동 확인한다.
추측으로 IME 호환성, 한컴 완전 일치 또는 안전 재저장 완료를 선언하지 않는다.

## 구현 순서

A. 세션 ABI와 원자적 텍스트 명령·보존 검사
B. Undo/Redo와 revision·오류 복원
C. 클릭 위치·좌표 변환·커서 및 문단 내 선택
D. 한글 입력·문단 분할/병합·일반 텍스트 붙여넣기
E. 작업실 편집 모드, 닫기 보호, 수정 후 PDF 및 실제 문서 검증

이 설계를 검토한 뒤 상세 구현 계획을 작성한다.
