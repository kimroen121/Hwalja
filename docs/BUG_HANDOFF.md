# 남은 버그와 점검

기준: `make test` 통과(Rust 50, Swift 50, 선택 실행 각 2개 제외). 앱을 바꾼 뒤에는 `make engine`과 `make run`으로 엔진과 앱을 함께 다시 만든다.

## 수동 점검 (자동화하지 못함)

확인됨(2026-10-05): ⌘F 포커스, 아랍어 표시, 그림 이동.

- [ ] 자동 저장과 창 닫기 저장: 입력·그림 이동 직후 닫고 다시 열어 같은지 확인.
- [ ] 실제 macOS 한글 입력기: ⌘A 후 입력이 전체를 교체하는지(필드가 있는 문서 포함), 조합→확정→Undo가 한 단계인지.
- [ ] 수식을 끌어 글 사이로 옮기기, 글자처럼 취급 그림을 끌었을 때 그대로인지.
- [ ] 문단 모양 대화상자(높이 400)가 기본·테두리/배경 두 탭에서 잘리지 않는지.

## 남은 문제

| 순위 | 문제 | 메모 |
|---|---|---|
| P1 | 글상자·각주·머리말 안 개체를 선택·크기 조절할 수 없음 | `ObjectRef`는 본문과 표 칸 옆에 뜬 개체만 가리킴 |
| P1 | 편집 실패가 경고음으로만 끝남 | 설명 문구를 넣지 않는 원칙과 맞물려 표시 방식을 먼저 정해야 함 |
| P2 | 띄어쓰기가 넓어 보임 | 엔진(rhwp)이 한컴 규약대로 공백을 글자 크기의 절반으로 잡음(함초롬바탕 실제 공백은 0.3em). 줄 나눔이 한컴과 달라지므로 바꾸지 않았음. 보기 전용 조정이 필요하면 결정 필요 |
| P2 | 글자처럼 취급 그림은 끌어 옮길 수 없음 | 수식만 글 사이로 옮김(`moveObject`). 그림은 이진 자료가 늘어나 보류 |
| P3 | 서로 다른 컨테이너를 넘는 선택 | 끌어 선택은 경계에서 멈춤 |

## 해결한 것 (참고)

전체 선택 후 입력(필드·마지막 빈 문단이 있는 문서: 사이 문단은 통째로 지움), 끌 때 글자처럼 취급이 꺼지던 것, 수식 이동, 문단 모양 대화상자 높이, 도구 상자 여백, 기본 탭 구성(웹 한글 화면 기준, 차트·웹 동영상·하이퍼링크 제외). 저장 장벽, 한글 조합 확정, 전체 선택(마지막 문단이 비어 있는 문서), 그림 이동 뒤 글자 커서 고정, 크기 고정 조절점 숨김, 그림 모서리 비율(그림은 기본 유지·Shift로 자유, 도형은 반대), 표 칸 안 그림 삽입, 프로토콜 버전 2, 잘라내기 선택 확인, 검색 결과 역전 방지, 찾기 막대 포커스 재요청, 복합 문자 경로, 크기 고정 거부, 화면 의존 배율 테스트. 회귀 테스트는 `Tests/DocumentTests.swift`, `Tests/EditSessionTests.swift`, 엔진 `editing/tests.rs`.
