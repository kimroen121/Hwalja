# 남은 버그와 점검

기준: `make test` 통과. 앱을 바꾼 뒤에는 `make engine`과 `make run`으로 엔진과 앱을 함께 다시 만든다. 편집 실패는 경고음으로 알린다(결정됨).

## 2026-10-06 빠른 서식 점검

- 진하게: 버튼과 `⌘B` 모두 선택 범위의 서식을 바꾸고, 저장뿐 아니라 화면 표시용 글꼴 face도 regular에서 bold용 face로 바뀌는 자동 테스트를 추가했다. Pretendard Variable은 PDF 엔진이 weight axis를 직접 만들지 못해 bold에서 다른 설치 글꼴로 대체될 수 있다. 따라서 굵기는 적용되지만 한컴과 획·폭이 완전히 같지는 않을 수 있다.
- 전체 선택 후 입력: 한글 조합 중인 마지막 글자가 있어도 기존 내용을 통째로 바꾸는 회귀 테스트가 있다.
- 머리말·꼬리말: 본문으로 잘못 판정되어 그림·표·도형·쪽 나누기가 활성화되던 문제를 수정했다. 엔진이 지원하지 않는 이름 있는 스타일 선택도 비활성화했다. 글꼴·크기·진하게 등 글자/문단 서식은 계속 사용할 수 있다.
- 기울임·밑줄·취소선·글자 크기는 엔진 서식/저장 경로의 테스트는 있으나, 이번 점검에서는 실제 앱 화면과 PDF까지의 픽셀 비교를 추가하지 못했다.

## 위치 규칙

엔진과 앱의 위치(`scalar`)는 글자 하나, 그리고 줄 안에 놓인 개체(글자처럼 취급 그림·수식·표·그리기 개체, 각주·미주 번호) 하나를 각각 한 칸으로 센다. rhwp의 본문 커서 함수가 이렇게 센다. 앱이 받는 문단 글자에는 개체 자리마다 U+FFFC가 들어 있고, 복사할 때는 빠진다. rhwp의 글자 편집 함수는 글자만 세므로 엔진(`editing/logical.rs`)이 바꿔 넘긴다. rhwp의 클릭·줄·선택 영역·칸 커서 함수는 개체 다음 줄부터(칸에서는 더) 위치를 다르게 세므로, 줄 안 개체가 있는 문단은 엔진이 쪽 배치(`get_page_text_layout_native`, `get_page_control_layout_native`)로 멈춤점을 직접 만들어 쓴다(`editing/stops.rs`, 수정 번호별 캐시). 실제 문서 47개에서 커서→클릭 왕복이 같은 문단 안에서 어긋난 것은 13,039곳 중 15곳(개체 없는 문단 27,583곳 중 20곳과 같은 수준).

## 수동 점검 (자동화하지 못함)

- [ ] 글자처럼 취급 그림 바로 뒤를 눌러 입력: 그림 뒤에 들어가는지. 그림 앞에서 입력하면 앞에 들어가는지.
- [ ] 글자처럼 취급 그림·수식을 끌기: 끄는 동안 놓일 자리에 옅은 커서가 따라오고, 놓으면 그 글자 자리로 옮겨지는지(표 칸 안으로도).
- [ ] 표 칸 안에서 그림·수식 넣기: 칸 안 커서 자리에 들어가는지.
- [ ] 캡션 넣기: 그림 아래 「그림 1」이 보이고 커서가 그 끝에 서서 바로 고쳐 쓸 수 있는지. 표도 같은지. 캡션을 눌러 고칠 수 있는지.
- [ ] 개체를 포함해 글자를 지우기(Backspace·범위 선택 후 입력): 개체도 지워지고 뒤 글자 서식이 그대로인지.
- [ ] 머리말·꼬리말 글자를 더블클릭: 단어가 선택되고 입력·Enter·Backspace·서식이 그 안에서만 되는지, 쪽 번호가 지워지지 않는지, 본문을 누르면 빠져나오는지.
- [ ] 서식 있는 복사·붙이기: 같은 문서에서 표·그림이 섞인 글을 복사해 붙이면 그대로 오는지, 다른 앱(Pages·웹 브라우저)과 주고받을 때 굵게·기울임이 유지되는지. 개체를 선택해 ⌘C/⌘X 후 붙이기.
- [ ] 직선을 선택하면 양 끝에 핸들이 보이고, 끝점을 끌면 다른 끝은 그대로인지.
- [ ] 글머리표 모양…·문단 번호 모양…: 고른 모양이 들어가는지, 새 번호 목록 시작과 1수준 시작 번호.
- [ ] 글자 모양의 언어와 서식 도구 상자의 「대표」: 영문만 다른 글꼴로 바꿀 수 있는지.
- [ ] 머리말·꼬리말 편집 중 빠른 메뉴의 지우기·다음/이전·닫기.

## 남은 문제

| 순위 | 문제 | 메모 |
|---|---|---|
| P1 | 서식의 한컴 시각 일치 검증 부족 | 진하게는 화면 표시용 face 변경까지 검증. 기울임·밑줄·취소선·글자 크기·색·형광펜은 HWP/HWPX 저장 후 한컴독스 PDF와 시각 비교 필요 |
| P1 | 가변 글꼴의 굵기/기울임 축 미지원 | 화면 표시 목록과 PDF 경로가 파일+face index만 전달하고 variation axis를 전달하지 않음. Pretendard Variable bold는 현재 다른 글꼴 fallback이라 줄 폭이 달라질 수 있음 |
| P2 | 혼합 서식 선택 표시 | 선택 범위 전체를 합산하지 않고 선택 끝의 서식을 툴바에 표시함. 일부만 굵은 범위를 잡았을 때 혼합/미정 상태를 보여 주지 못함 |
| P2 | 머리말·꼬리말 보호 필드 수동 점검 | 쪽 번호·파일 이름 필드를 포함해 전체 선택 후 입력/잘라내기 했을 때 보호 필드는 유지되고 일반 글자만 바뀌는지 한컴 문서로 확인 필요 |
| P2 | 띄어쓰기가 넓어 보임 | 엔진(rhwp)이 한컴 규약대로 공백을 글자 크기의 절반으로 잡음(함초롬바탕 실제 공백은 0.3em). 줄 나눔이 한컴과 달라지므로 바꾸지 않았음. 보기 전용 조정이 필요하면 결정 필요 |
| P3 | 서로 다른 컨테이너를 넘는 선택 | 끌어 선택은 경계에서 멈춤 |
| P3 | 테스트용으로 만든 hwp 문서에 그림을 넣으면 쪽이 늘어남 | 실제 문서 47개에서는 생기지 않음(rhwp 생성 hwp의 줄 정보 문제로 보임) |
