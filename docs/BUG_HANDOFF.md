# 남은 버그와 점검

기준: `make test` 통과(Rust 53, Swift 51, 선택 실행 각 2개 제외). 앱을 바꾼 뒤에는 `make engine`과 `make run`으로 엔진과 앱을 함께 다시 만든다.

## 수동 점검 (자동화하지 못함)

- [ ] 실제 macOS 한글 입력기: 조합→확정→Undo가 한 단계인지.
- [ ] 글자처럼 취급 그림을 끌었을 때 그대로인지(크기 조절만 됨).
- [ ] 표 칸·글상자 안 그림, 표 칸 안 수식을 눌러 선택·크기 조절·개체 속성·지우기(그림만).
- [ ] 도구 상자: 화살표 있는 도구는 이름 한 줄 + 아래 화살표, 없는 도구는 이름 두 줄까지, 모든 도구의 높이가 같은지.

## 남은 문제

| 순위 | 문제 | 메모 |
|---|---|---|
| P1 | 편집 실패가 경고음으로만 끝남 | 설명 문구를 넣지 않는 원칙과 맞물려 표시 방식을 먼저 정해야 함 |
| P2 | 띄어쓰기가 넓어 보임 | 엔진(rhwp)이 한컴 규약대로 공백을 글자 크기의 절반으로 잡음(함초롬바탕 실제 공백은 0.3em). 줄 나눔이 한컴과 달라지므로 바꾸지 않았음. 보기 전용 조정이 필요하면 결정 필요 |
| P2 | 글자처럼 취급 그림은 끌어 옮길 수 없음 | 수식만 글 사이로 옮김(`moveObject`). 그림은 이진 자료가 늘어나 보류 |
| P2 | 선택할 수 없는 개체: 각주·머리말 안, 중첩 표 칸 안, 칸·글상자 안 도형, 칸 문단에 수식이 둘 이상일 때의 수식, 칸 안 수식 지우기 | rhwp의 칸 수식 함수는 그 문단의 첫 수식만 찾고 지우기 함수가 없음. 실제 문서 47개에서 각주·머리말 안 개체 0개, 중첩 칸 그림 4개 |
| P3 | 서로 다른 컨테이너를 넘는 선택 | 끌어 선택은 경계에서 멈춤 |
