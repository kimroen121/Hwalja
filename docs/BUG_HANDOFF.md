# 남은 버그와 점검

기준: `make test` 통과. 앱을 바꾼 뒤에는 `make engine`과 `make run`으로 엔진과 앱을 함께 다시 만든다. 편집 실패는 경고음으로 알린다(결정됨).

## 위치 규칙

엔진과 앱의 위치(`scalar`)는 글자 하나, 그리고 줄 안에 놓인 개체(글자처럼 취급 그림·수식·표·그리기 개체, 각주·미주 번호) 하나를 각각 한 칸으로 센다. rhwp의 본문 커서 함수가 이렇게 센다. 앱이 받는 문단 글자에는 개체 자리마다 U+FFFC가 들어 있고, 복사할 때는 빠진다. rhwp의 글자 편집 함수는 글자만 세므로 엔진(`editing/logical.rs`)이 바꿔 넘긴다. rhwp의 클릭·줄·선택 영역·칸 커서 함수는 개체 다음 줄부터(칸에서는 더) 위치를 다르게 세므로, 줄 안 개체가 있는 문단은 엔진이 쪽 배치(`get_page_text_layout_native`, `get_page_control_layout_native`)로 멈춤점을 직접 만들어 쓴다(`editing/stops.rs`, 수정 번호별 캐시). 실제 문서 47개에서 커서→클릭 왕복이 같은 문단 안에서 어긋난 것은 13,039곳 중 15곳(개체 없는 문단 27,583곳 중 20곳과 같은 수준).

## 수동 점검 (자동화하지 못함)

- [ ] 글자처럼 취급 그림 바로 뒤를 눌러 입력: 그림 뒤에 들어가는지. 그림 앞에서 입력하면 앞에 들어가는지.
- [ ] 글자처럼 취급 그림·수식을 끌기: 끄는 동안 놓일 자리에 옅은 커서가 따라오고, 놓으면 그 글자 자리로 옮겨지는지(표 칸 안으로도).
- [ ] 표 칸 안에서 그림·수식 넣기: 칸 안 커서 자리에 들어가는지.
- [ ] 캡션 넣기: 그림 아래 「그림 1」이 보이고 커서가 그 끝에 서서 바로 고쳐 쓸 수 있는지. 표도 같은지. 캡션을 눌러 고칠 수 있는지.
- [ ] 개체를 포함해 글자를 지우기(Backspace·범위 선택 후 입력): 개체도 지워지고 뒤 글자 서식이 그대로인지.
- [ ] 머리말·꼬리말 글자를 더블클릭: 단어가 선택되고 입력·Enter·Backspace·서식이 그 안에서만 되는지, 쪽 번호가 지워지지 않는지, 본문을 누르면 빠져나오는지.

## 남은 문제

| 순위 | 문제 | 메모 |
|---|---|---|
| P2 | 띄어쓰기가 넓어 보임 | 엔진(rhwp)이 한컴 규약대로 공백을 글자 크기의 절반으로 잡음(함초롬바탕 실제 공백은 0.3em). 줄 나눔이 한컴과 달라지므로 바꾸지 않았음. 보기 전용 조정이 필요하면 결정 필요 |
| P3 | 서로 다른 컨테이너를 넘는 선택 | 끌어 선택은 경계에서 멈춤 |
| P3 | 테스트용으로 만든 hwp 문서에 그림을 넣으면 쪽이 늘어남 | 실제 문서 47개에서는 생기지 않음(rhwp 생성 hwp의 줄 정보 문제로 보임) |
