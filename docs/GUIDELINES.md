# 작업 지침

HwpStudio에서 일하는 사람(사람과 에이전트 모두)이 지키는 방식이다. 목표와 할 일은 `ROADMAP.md`, 내부 문제와 수동 점검은 `BUG_HANDOFF.md`.

## 무엇을 만드는가

- 원본을 훼손하지 않는 macOS 네이티브 HWP/HWPX 편집기. 조판은 한컴 뷰어와 같게, UI는 Apple HIG를 따른다.
- 앱 안에 설명 문구를 넣지 않는다. 지연과 깜빡임은 버그다.
- 기능의 동작과 대화상자 구성은 한컴 공식 도움말(<https://help.hancom.com/hoffice/multi/ko_kr/hwp/index.htm>, 한컴오피스 NEO 한글)을 기준으로 한다. 도움말과 다르게 만든 부분은 ROADMAP이나 BUG_HANDOFF에 이유를 적는다.

## 용어

- 메뉴·단추·대화상자 이름은 웹 한글(`~/Downloads`의 저장 htm, main.js, 스크린샷)에서 그대로 가져온다. 웹 한글에 없는 대화상자 안의 문구는 한컴 도움말에서 가져온다.
- 새 용어를 만들지 않는다. 확인할 수 없는 이름은 아이콘이나 견본으로 대신하고, 그것도 안 되면 이름을 확인할 때까지 보류한다.
- macOS 표준 명령(프린트…, PDF로 내보내기…, 확인·취소)은 macOS 이름을 쓴다. 한글 고유의 연속 단축키(Ctrl+N,S 등)는 쓰지 않는다.

## 일하는 순서

1. ROADMAP에서 눈에 보이는 기능부터 고른다. 내부 정리·디버깅은 BUG_HANDOFF에 체계적으로 적어 두기만 하고, 필요할 때 처리한다.
2. 코드를 바꾸기 전에 그 기능의 실제 흐름(엔진 → 프로토콜 → 앱)을 끝까지 읽는다. 버그는 증상이 아니라 모든 호출자가 지나는 곳에서 고친다.
3. 기능마다 엔진 테스트와 앱 테스트를 하나씩 남긴다. 화면은 스냅샷(`HWP_SNAPSHOT_DIR`)으로 직접 보고, 조판은 한컴에서 만든 PDF와 쪽마다 나란히 비교한다.
4. `make test`가 통과하면 커밋한다. 화면에서 손으로 확인하지 못한 것은 BUG_HANDOFF의 수동 점검에 적는다.
5. 끝난 항목은 ROADMAP·BUG_HANDOFF에서 지운다(기록은 git이 한다).

## 코드

- 주변 코드와 같은 이름·주석 밀도·관용구를 쓴다. 필요 없는 추상화, 나중을 위한 뼈대, 한 번만 쓰는 설정을 만들지 않는다.
- rhwp를 고칠 때는 `build/rhwp`에서 고친 뒤 `Vendor/rhwp-layout.patch`를 다시 만들고 `Vendor/README.md`에 한 줄을 더한다. 생성된 `build/`는 커밋하지 않는다.
- 안전성을 확인할 수 없는 대상은 읽기 전용으로 두고, 풀 때는 보존 검사(`preservation.rs`)를 먼저 만든다.

## 커밋과 공유

- 커밋 제목 한 줄만 쓴다(`feat:`·`fix:`·`docs:` + 영어 설명, 한글 기능 이름은 그대로). 본문, 공동 작성자 줄은 붙이지 않는다.
- 판단해서 필요할 때 커밋한다. 푸시는 요청받았을 때만 하고, 다른 작업자의 커밋이 있으면 그 위에 다시 쌓아 합친다.
- 개인 문서와 비공개 문서 묶음은 저장소, 로그, 테스트 자료에 넣지 않는다. 로컬 검사(`HWP_CORPUS`, `HWP_SNAPSHOT_DOC`)에서만 쓴다.

## 보고

- 사용자에게는 한국어로 보고한다. 한 일, 확인한 방법, 확인하지 못한 것, 사용자에게 필요한 것(스크린샷, 견본 문서, 결정)을 나눠 적는다.
